## 🔴 Критические проблемы


---

### 2. Отсутствие CSP заголовков (XSS уязвимость)
**Файл:** `next.config.ts`, `src/app/layout.tsx`

**Проблема:** Content Security Policy не настроена. Это открывает возможность для XSS-атак через инъекцию вредоносных скриптов.

**Рекомендация:** Добавить CSP заголовки в `next.config.ts` или через middleware:
```typescript
headers: {
  'Content-Security-Policy': "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self' ws: wss:;"
}
```

---

### 3. Некриптографически безопасная генерация кодов верификации
**Файл:** `src/app/api/auth/send-verification/route.ts:30`

**Проблема:** `Math.random()` не является криптографически безопасным. Код верификации может быть предсказуем.

**Текущий код:**
```typescript
const code = Math.floor(100000 + Math.random() * 900000).toString();
```

**Рекомендация:** Использовать `crypto.randomInt()`:
```typescript
const code = crypto.randomInt(100000, 1000000).toString();
```

---

### 4. Отсутствие rate limiting на login endpoint
**Файл:** `src/app/api/login/route.ts`

**Проблема:** Endpoint `/api/login` не имеет rate limiting, в отличие от `/api/register`. Это позволяет брутфорс-атаки.

**Рекомендация:** Добавить rate limiting аналогично register:
```typescript
import { checkRateLimit, getRateLimitKey, getStrictConfig } from '@/lib/rate-limit';

const rlKey = getRateLimitKey(request, 'login');
const rl = await checkRateLimit(rlKey, getStrictConfig());
if (!rl.success) {
  return NextResponse.json({ error: 'Too many attempts' }, { status: 429 });
}
```

---

### 5. Избыточные запросы к БД в JWT callback
**Файл:** `src/auth.ts:36-52`

**Проблема:** При каждом входе делается дополнительный запрос к БД для загрузки `role` и `avatar`. Эти данные уже загружены в `authorize` callback.

**Рекомендация:** Передавать `role` и `avatar` из `authorize` callback через токен или кэшировать результат.

## 🟡 Высокий приоритет

### 6. Неиспользуемая функция getSocket()
**Файл:** `src/lib/socket-client.ts:134-136`

**Проблема:** Функция `getSocket()` всегда возвращает `null` и не используется. Это мёртвый код.

**Рекомендация:** Удалить функцию или реализовать корректно.

---

### 7. Отсутствие обработки ошибок в PostForm
**Файл:** `src/components/PostForm.tsx:88-92`

**Проблема:** При ошибке создания поста пользователь не получает уведомление.

**Текущий код:**
```typescript
} catch (error) {
  console.error("Failed to create post:", error);
} finally {
```

**Рекомендация:** Добавить showAlert для ошибки:
```typescript
} catch (error) {
  console.error("Failed to create post:", error);
  showAlert("Не удалось опубликовать пост");
}
```

---

### 8. Отсутствие rate limiting на API вызовы в Sidebar
**Файл:** `src/components/Sidebar.tsx:93-121`

**Проблема:** Периодические вызовы `/api/users/me`, `/api/notifications`, `/api/messenger/unread` не имеют rate limiting. При большом количестве пользователей это создаст нагрузку.

**Рекомендация:** Добавить client-side throttling или server-side rate limiting.

---

### 9. Отсутствие rate limiting на скачивание файлов
**Файл:** `src/app/api/files/[...path]/route.ts`

**Проблема:** Endpoint раздачи файлов не имеет rate limiting. Возможна DoS-атака через скачивание больших файлов.

**Рекомендация:** Добавить rate limiting на основе IP.

---

### 10. In-memory кэш не работает в multi-instance окружении
**Файл:** `src/lib/cache.ts`

**Проблема:** Кэш хранится в памяти процесса. При горизонтальном масштабировании кэш не будет синхронизирован между инстансами.

**Рекомендация:** Использовать Redis или аналогичное решение для распределённого кэша.

---

### 11. In-memory rate limiter не работает в multi-instance окружении
**Файл:** `src/lib/rate-limit.ts`

**Проблема:** Rate limiter хранит состояние в памяти процесса. При горизонтальном масштабировании лимиты не будут работать корректно.

**Рекомендация:** Использовать Upstash Redis (код уже подготовлен для этого) или аналогичное решение.

---

## 🟢 Средний приоритет

### 12. Отсутствие валидации длины пароля в Prisma schema
**Файл:** `prisma/schema.prisma:13`

**Проблема:** Поле `password` в модели `User` не имеет ограничения длины. Хотя bcrypt хеш фиксированной длины, валидация на уровне БД отсутствует.

**Рекомендация:** Добавить ограничение через `@db.VarChar(60)` или оставить как есть (не критично).

---

### 13. Path traversal защита в files endpoint может быть обойдена
**Файл:** `src/app/api/files/[...path]/route.ts:14-19`

**Проблема:** Защита от path traversal использует `path.resolve()` и `startsWith()`. Это корректно, но можно добавить дополнительную проверку на наличие `..` в пути.

**Рекомендация:** Добавить проверку:
```typescript
if (pathSegments.some(seg => seg.includes('..'))) {
  return new NextResponse('Forbidden', { status: 403 });
}
```

---

### 14. Отсутствие CORS конфигурации
**Файл:** `next.config.ts`

**Проблема:** Нет явной конфигурации CORS. Next.js обрабатывает это автоматически, но для production рекомендуется явная настройка.

**Рекомендация:** Добавить CORS middleware или конфигурацию.

---

### 15. Отсутствие логирования ошибок
**Все файлы**

**Проблема:** Ошибки логируются только в `console.error`. В production это не достаточно.

**Рекомендация:** Интегрировать систему логирования (Winston, Pino, Sentry).

---

### 15. Отсутствие health check endpoint
**Файл:** отсутствует

**Проблема:** Нет endpoint для проверки здоровья приложения (health check).

**Рекомендация:** Добавить `/api/health` endpoint.
