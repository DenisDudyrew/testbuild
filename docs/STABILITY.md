# Состояние стабилизации Zephyr

Решения владельца: один сервер с Docker Compose, одна PostgreSQL, резервное копирование пока пропускаем. SMTP-пароль оставлен в конфигурации. Бэкенд перенесён на Go, фронтенд остаётся React/Next.js.

## Подготовлено

- Go обслуживает все прикладные API: аккаунты, посты, ленты, комментарии, подписки, закладки, опросы, уведомления, мессенджер, файлы и администрирование. Проверка списка старых маршрутов не даёт незаметно забыть endpoint.
- Серверные сессии вместо NextAuth; cookie HttpOnly/SameSite, проверка Origin для изменений, отзыв сессий при выходе/смене пароля/удалении аккаунта.
- Регистрация подтверждается одноразовым cookie-доказательством; нельзя заменить пароль завершённого аккаунта через подтверждённый email.
- AES-256-GCM, SHA-256 нормализованного email и bcrypt совместимы с прежним Node API. Совместимость проверяется фикстурой, созданной прежними библиотеками.
- SQL-запросы параметризованы. Связанные записи выполняются транзакциями, конкурирующие изменения используют блокировки/Serializable и повтор при конфликте.
- Постоянные ID сообщений и безопасный повтор по tempId. Индивидуальное скрытие, фильтрация скрытых/удалённых сообщений, проверка ответа/пересылки и блокировки собеседника.
- SSE вместо Socket.IO: сервер публикует сохранённые сообщения только участникам; проверка участия перед выдачей события, ограниченные очереди, переподключение и сверка с БД. Отдельный брокер не нужен.
- Приватное хранилище вне public; метаданные владельца в той же БД; старые URL защищены тем же ACL. Публикация чужого приватного URL запрещена. Нет общего image cache, есть range/HEAD и безопасная выдача документов.
- Исправления ленты и мессенджера: пагинация без пропуска при ошибке, отсутствие дублей, сохранение черновика, естественная высота сообщений, поиск и переход из уведомлений.
- Миграции встроены в Go; прежняя история Prisma распознаётся, ID/пароли/переписка не сбрасываются. Demo seed не запускается.
- Docker содержит Go API и внутренний Next.js, снаружи открыт один порт. Healthcheck проверяет БД, deployment использует конкретный SHA, PR не заменяет production-образ.

## Проверки перед push

- Go API с фактическим SQL и миграциями на PostgreSQL/WASM в памяти; сохранность учётной записи при переходе с истории Prisma; повтор миграций.
- Старые маршруты покрыты новым registry; OpenAPI формируется из этого же registry.
- Проверка конкурентного доступа (`go test -race`), `go vet`, тесты React, линтер, production-сборка.
- Настоящий браузер с Go API: два аккаунта, публикация и двусторонняя доставка сообщений через SSE быстрее периодического опроса, проверка 390/700/1440 px.
- Постоянной второй базы и отдельного развёрнутого стенда нет. Тестовые данные существуют только в памяти процесса.

## При обновлении единственного сервера

1. Обновить образ и compose, оставив прежние DATABASE_URL, ENCRYPTION_KEY, SMTP и том uploads.
2. Тот же именованный том монтируется в /app/uploads. Не перемонтировать его обратно в public. Не выполнять down -v.
3. Entrypoint выполняет `./zephyr migrate`; в существующей PostgreSQL добавляются поля видимости, Upload, таблицы сессий/истории миграций и порядок вариантов опроса. Все миграции выполняются без сброса пользовательских таблиц.
4. После обновления войти заново: старые NextAuth cookie не являются Go-сессиями. Пароли сохраняются.
5. Проверить healthy и реальную SMTP-доставку. Пароль в конфигурации сохранён по решению владельца.
6. Проверить два аккаунта, вложение чата и его старую ссылку. Внешний nginx/CDN не должен раздавать uploads через alias или общий кеш; все запросы должны идти в Go.

## Что остаётся после переноса

- Подтвердить на самом сервере Docker-сборку/развёртывание, применение миграций и SMTP; локальная Docker-служба может отсутствовать, это не заменяется тестом SQL в памяти.
- Проверить старые demo-аккаунты и при необходимости самостоятельно заменить/удалить известные пароли. Автоматически существующие пароли не меняем.
- Подключить сбор эксплуатационных ошибок без паролей, кодов и содержимого переписки. Go выдаёт request ID и не возвращает внутренние SQL-ошибки клиенту.
- Измерить p50/p95 API, SQL, память и CPU на реальном объёме. Сам перенос на Go не является доказательством ускорения.
- Проверить SSE на внешнем nginx: без буферизации, с достаточным idle timeout. Go отправляет heartbeat каждые 15 секунд.
- Решить отдельно, нужен ли отказ от открытого searchContent. Сейчас это серверное шифрование поля, не сквозное шифрование.
- Если к резервному копированию вернёмся позже, включить PostgreSQL, приватные/старые файлы и ENCRYPTION_KEY.

## Откат

Безопасный откат — на проверенную Go-сборку с теми же ACL и расположением файлов. Возвращение к старому Node API может снова открыть приватные вложения; не менять том обратно в public ради такого отката. Новые таблицы/поля не удалять автоматически. Откат SQL и восстановление данных сейчас не выполняются.
