# Zephyr

Небольшая социальная сеть: React/Next.js для интерфейса, **Go для всего API, сессий, загрузки файлов и событий мессенджера**, одна PostgreSQL. Один Docker Compose и один стенд. SMTP-настройки сохранены в конфигурации по решению владельца.

## Запуск через Docker Compose

```sh
docker compose up -d --build
```

Приложение доступно на порту 3000. Go принимает внешние запросы; внутренний Next.js слушает только 127.0.0.1:3001 в том же контейнере. Публиковать порт интерфейса отдельно не требуется. Redis и брокер сообщений не используются.

Production-конфигурация — `docker-compose.prod.yml`, каталог установки — `/opt/testbuild`. Переменные окружения остаются в существующем `.env`. `IMAGE_TAG` позволяет выбрать образ конкретного коммита.

При старте `./zephyr migrate` применяет миграции **к той же базе**, затем запускается Go API и процесс интерфейса. Demo seed и Prisma в рантайме больше не используются.

## Локальная разработка

Нужны Node.js 22+, Go 1.27.4 и существующая PostgreSQL. Создать `.env` с настройками установки, затем:

```sh
npm ci
npm run db:migrate
npm run dev
```

Go API: `http://localhost:3000`; внутренний интерфейс: `http://127.0.0.1:3001`. Открывать приложение через порт Go. Изменения Go требуют перезапуска `npm run dev`; интерфейс обновляется автоматически. Можно задать `GO_BINARY`, если Go находится не в PATH.

Основные настройки:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Единственная PostgreSQL |
| `AUTH_SECRET` | Секрет для подтверждения email |
| `AUTH_URL` | Внешний адрес приложения; поддерживается прежний `NEXTAUTH_URL` |
| `ENCRYPTION_KEY` | Существующий ключ AES; сохранить при обновлении |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Отправка кодов подтверждения |
| `SMTP_TLS`, `SMTP_FROM`, `SMTP_FROM_NAME` | TLS и отправитель SMTP |
| `UPLOAD_DIR` | Приватное хранилище, по умолчанию `./uploads` |
| `LEGACY_UPLOAD_DIR` | Прежние файлы, по умолчанию `./public/uploads` |
| `API_ADDR` | Адрес Go, в Docker `0.0.0.0:3000` |
| `UI_ORIGIN` | Внутренний адрес Next.js |

Порты SMTP 465 (TLS) и 587 (STARTTLS) поддерживаются. Ошибки SMTP не раскрывают пароль в ответе API.

## Обновление существующей установки

- Старые ID, bcrypt-хэши паролей и формат AES-256-GCM сохранены. Менять пароли пользователей не требуется.
- При первом запуске Go нужно **войти заново**: вместо NextAuth используются серверные сессии в PostgreSQL.
- Старые миграции перенесены в `backend/migrations`. Мигратор распознаёт завершённые записи `_prisma_migrations` и не выполняет их повторно. Новые записи ведутся в `_zephyr_migrations`. SQL-миграции встроены в Go-бинарник.
- Именованный том `uploads` сохранён и монтируется в `/app/uploads`. Не удалять его и не выполнять `down -v` для обновления. Старые ссылки работают через проверку прав.
- Все `/api/*` обслуживает Go; неизвестный API-маршрут не пересылается в старую реализацию.
- Откат к Node API до защиты вложений небезопасен. Откатывать следует на сборку с теми же проверками прав и расположением хранилища.
- По решению владельца резервное копирование на этом этапе пропускается. Миграции не требуют сброса данных.

## Первый администратор

Сначала создать обычный аккаунт через интерфейс, затем назначить его администратором локальной операторской командой:

```sh
docker compose exec -e ADMIN_USERNAME=your_username app ./zephyr promote-admin
```

Для production добавить `-f docker-compose.prod.yml` после `docker compose`. Команда не меняет пароль и не создаёт аккаунт с заранее известным паролем. Через HTTP она недоступна.

## API и realtime

Реализация — `backend/internal/server`, точка входа — `backend/cmd/zephyr`. Основные группы: аккаунты, лента и посты, комментарии, опросы, профили, уведомления, мессенджер, файлы, администрирование.

- Вход: `POST /api/auth/login`, сессия: `GET /api/auth/session`, выход: `POST /api/auth/logout`.
- Смена пароля: `PUT /api/users/me/password` с `currentPassword` и `newPassword`. Старые сессии отзываются.
- SSE: `GET /api/events`, события `message:new`, `messages:changed`, `conversation:update`, `typing:update`. Отправка и изменение данных остаются HTTP-запросами. Клиент сверяет состояние после переподключения.
- `GET /api/health` проверяет PostgreSQL. Docker и deployment ждут healthy.
- Документ маршрутов: [docs/openapi.json](docs/openapi.json). Перегенерация: `go -C backend run ./cmd/zephyr openapi`.

## Файлы и защита данных

Новые загрузки приватны до прикрепления. Метаданные владельца хранятся в той же PostgreSQL. Файлы чата доступны только участникам, которым видно сообщение; файлы опубликованных постов/профилей — вошедшим пользователям. Знание приватного URL не разрешает публикацию в чужом посте или профиле.

Go защищает `/api/files` и старый `/uploads`, включая кодированные пути, проверяет размер/сигнатуру, не использует общие URL для одинаковых байтов, запрещает симлинки и отдаёт документы как скачивание. Поддерживаются HEAD и диапазоны для видео. Приватная выдача не кешируется. Next Image optimizer выключен, чтобы не создавать общий кеш приватных изображений.

Сообщения шифруются на сервере в прежнем формате AES-256-GCM. Поисковый индекс `searchContent` остаётся открытым в базе. Это **не сквозное шифрование**. Не менять `ENCRYPTION_KEY`, если нужно читать прежнюю переписку.

## Проверки

```sh
npm test
npm run lint
npm run build
go -C backend test -race ./...
go -C backend vet ./...
```

Go-интеграционные тесты выполняют миграции и SQL в PostgreSQL/WASM **в памяти** через PGlite. Нет постоянной тестовой базы, сетевого PostgreSQL-сервера или доступа к пользовательским данным. Для этих тестов нужен `npm ci` и Node.js; для production PGlite не нужен.

Полный браузерный прогон после сборки:

```sh
npx playwright install chromium
npm run test:browser
```

Он запускает временные процессы интерфейса и Go API с PostgreSQL в памяти, открывает два независимых аккаунта и проверяет вход, публикацию, доставку SSE и мобильную компоновку. Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` для установленного Chrome. Эти же проверки включены в GitHub Actions перед сборкой образа и развёртыванием.

Оставшиеся эксплуатационные проверки — [docs/STABILITY.md](docs/STABILITY.md).
