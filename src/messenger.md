Анализ мессенджера: проблемы и рекомендации
Критические проблемы

Файлы: encryption.ts, route.ts

2. Поиск по зашифрованным сообщениям не работает
Текущая реализация: route.ts использует contains на зашифрованном контенте - это никогда не найдет ничего.

Как должно быть:

Хранить полнотекстовый индекс в отдельной таблице (зашифрованный или с отдельным ключом)
Или использовать клиентский поиск при загрузке всех сообщений
Или использовать searchable encryption (deterministic encryption для поиска)
Файл: route.ts

3. Отсутствие пагинации сообщений
Текущая реализация: ChatView.tsx загружает все сообщения сразу без cursor-based pagination.

Как должно быть: Как в Telegram - загрузка порциями (например, 50 сообщений) с infinite scroll при прокрутке вверх.

Файл: ChatView.tsx:104-124

4. Оптимистичный UI не синхронизируется с сервером
Текущая реализация: Сообщение добавляется с tempId, но после успешного ответа не заменяется на реальное серверное сообщение.

Как должно быть: Заменять temp-сообщение на реальное по ID или использовать UUID на клиенте и сопоставлять с сервером.

Файл: ChatView.tsx:215-268

5. Отсутствие подтверждения прочтения (read receipts)
Текущая реализация: CheckCheck в MessageBubble.tsx всегда показывается для своих сообщений, не отражая реальный статус.

Как должно быть: Как в Telegram - одна галочка = отправлено, две = доставлено, две синие = прочитано. Требуется отдельная таблица MessageDeliveryStatus.

Файл: MessageBubble.tsx:190-192

6. Отсутствие виртуализации списка
Текущая реализация: Все сообщения рендерятся в DOM. При 1000+ сообщений будут лаги.

Как должно быть: Использовать react-window или react-virtualized для рендеринга только видимых сообщений.

Файл: ChatView.tsx:492-504

Средние проблемы
7. Отсутствие истории редактирований
Текущая реализация: Только editedAt timestamp.

Как должно быть: Таблица MessageEditHistory с возможностью посмотреть "изменено" и увидеть оригинал (как в Telegram).

8. Удаление только "для всех"
Текущая реализация: Только soft-delete без выбора.

Как должно быть: Опция "удалить для меня" vs "удалить для всех" (как в Telegram).

9. Отсутствие пересылки сообщений
Текущая реализация: Нет функции forward.

Как должно быть: Кнопка "Переслать" с выбором чата и сохранением ссылки на оригинал.

10. Отсутствие голосовых сообщений
Текущая реализация: Поддерживаются только image/video/file.

Как должно быть: Запись аудио с визуализацией waveform (как в WhatsApp/Telegram).

11. Отсутствие упоминаний (@username)
Текущая реализация: Нет функции mention.

Как должно быть: Парсинг @username в группах с уведомлениями упомянутым пользователям.

12. Отсутствие push-уведомлений
Текущая реализация: Нет push-уведомлений о новых сообщениях.

Как должно быть: Web Push API + FCM/APNs для мобильных.

13. Online статус не real-time
Текущая реализация: Определяется по lastSeenAt с таймаутом 2 минуты. Handler onOnlineUpdate есть в socket, но не используется.

Как должно быть: Real-time обновления через socket с heartbeat механизмом.

Файлы: socket-client.ts:71-73, ChatView.tsx:309-312

14. Отсутствие блокировки пользователей
Текущая реализация: Нет функции block/unblock.

Как должно быть: Таблица UserBlock с фильтрацией сообщений от заблокированных.

15. Отсутствие архива чатов
Текущая реализация: Все чаты в основном списке.

Как должно быть: Архив для неактивных чатов (как в Telegram).

16. Отсутствие pinned chats
Текущая реализация: Можно пиннуть сообщения, но не чаты.

Как должно быть: Пин чатов в верх списка с полем pinnedOrder в Conversation.

17. Отсутствие mute чатов
Текущая реализация: Нет отключения уведомлений для конкретного чата.

Как должно быть: Поле mutedUntil в ConversationParticipant.

18. Отсутствие draft сообщений
Текущая реализация: При переключении чатов текст теряется.

Как должно быть: Сохранение draft в ConversationParticipant.draftContent.

19. Нет визуализации проблем с соединением
Текущая реализация: При отключении socket fallback на polling без индикации.

Как должно быть: Показывать "connecting..." / "reconnecting..." статус.

20. Отсутствие retry механизма
Текущая реализация: При неудачной отправке нет автоматического повтора.

Как должно быть: Очередь неудачных сообщений с exponential backoff retry.

Мелкие UX проблемы
21. Отсутствие preview ссылок
Нет генерации OpenGraph preview для URL в сообщениях.

22. Отсутствие форматирования текста
Нет markdown/bold/italic/mono.

23. Отсутствие разделителей даты
Только один разделитель для первого сообщения. Нужно между сообщениями разных дней.

Файл: ChatView.tsx:480-490

24. Отсутствие unread divider
Нет разделителя "новые сообщения" для непрочитанных.

25. Отсутствие scroll to bottom button
При прокрутке вверх нет кнопки вернуться к новым сообщениям.

26. Отсутствие message context menu на mobile
Действия только при hover. Нужно long-press menu.

27. Отсутствие swipe actions
На mobile нет swipe для reply/delete.

28. Отсутствие экспорта чата
Нет возможности выгрузить историю (TXT/JSON).

29. Поиск только внутри текущего чата
Нет глобального поиска по всем чатам.

30. Отсутствие reply-цепочек
Есть replyTo, но нет визуального выделения всей цепочки ответов.

Архитектурные проблемы
31. Смешивание polling и socket
Текущая реализация: Fallback на polling с интервалами 15-30 секунд.

Как должно быть: Использовать только WebSocket с reconnect logic. Polling как fallback только для старых браузеров.

Файл: ChatView.tsx:166-177

32. Отсутствие кэширования на клиенте
Текущая реализация: При переключении чатов сообщения перезагружаются.

Как должно быть: IndexedDB или React Query для кэширования сообщений.

33. Отсутствие rate limiting
Текущая реализация: Нет ограничения на частоту отправки.

Как должно быть: Rate limiting на API (например, 30 сообщений/минуту).

34. N+1 запросы в conversations API
Текущая реализация: Отдельный запрос для unreadCount каждого чата.

Файл: route.ts:72-89

Как должно быть: Использовать агрегацию или подзапрос в Prisma.

35. Отсутствие валидации входных данных
Текущая реализация: Минимальная валидация на API.

Как должно быть: Zod или Joi схемы для всех endpoints.

Исправить поиск по сообщениям
Добавить пагинацию сообщений
Исправить оптимистичный UI
Добавить read receipts
Добавить виртуализацию списка
Средний приоритет: 6. Добавить историю редактирований 7. Добавить удаление "для себя" 8. Добавить forward 9. Добавить mention 10. Добавить push notifications 11. Реализовать real-time online статусы 12. Добавить block/unblock 13. Добавить archive чатов 14. Добавить pinned чаты 15. Добавить mute чатов 16. Добавить drafts 17. Добавить retry механизм

Низкий приоритет: 18-35. UX улучшения
